# Design Thinking

## Purpose

Use customer and product evidence to make the design decisions required by the selected prototype journey.

## Evidence to Design

Begin with the user's context, goal, pain, environment, device, and accessibility needs. Distinguish observed user evidence from personas or design assumptions.

Translate evidence into:

- the experience goal;
- information and action priority;
- the minimum screens and transitions for the core journey;
- feedback for important loading, empty, error, success, focus, and disabled states;
- responsive and accessibility behavior that affects use;
- visual direction needed to communicate the product or brand.

## Decision Criteria

- Use familiar language and interaction patterns for the target user unless the validation goal tests a new pattern.
- Keep system status, available actions, and recovery visible where the journey needs them.
- Define reusable components and tokens when consistency across the selected screens requires them.
- Select responsive behavior from the target devices and content rather than fixed breakpoints alone.
- Use the accessibility standard or organizational requirement supplied by the project. For public web experiences where the project leaves the standard open, use current WCAG Level AA guidance as the baseline and verify the current standard when exact conformance matters.

## Atmosphere Translation

When brand or atmosphere affects the prototype, connect each relevant attribute to concrete direction. Possible dimensions include color semantics, typography, spacing density, shapes, shadows, imagery, and motion.

Keep a translation when it changes the generated interface. Use references supplied by the user or found through approved research, and record which visual qualities are relevant rather than copying unrelated surface details.

## Validation

Select the smallest artifact that can answer the design question: a written direction, flow, wireframe, component specification, or interactive prototype. Record what users or stakeholders should be able to understand or do with it.

## Completion Criteria

- Design decisions trace to user, product, brand, accessibility, or validation evidence.
- The core journey and important states are usable and testable.
- Visual detail is proportional to the selected prototype.
- Assumptions and unresolved material decisions are visible.
